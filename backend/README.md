# Tajweed Coach AI — Backend Skeleton (v0.1)

هيكل API بسيط يوصل واجهة التطبيق (شاشة التلاوة) بمحرك التحليل، مبني بحيث
تقدر تطوّر الواجهة والمنتج كامل اليوم بدون ما تنتظر جاهزية الموديل الحقيقي.

## التشغيل محليًا

```bash
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

## الـ Endpoints

- `GET /health` — فحص إن السيرفر شغّال.
- `GET /api/ayah/{surah}/{ayah}` — يرجّع نص الآية مقسّم لكلمات (لعرضها بالواجهة).
  حاليًا فيها بس الفاتحة 1:1 (البسملة) — راجع `reference_data.py`.
- `POST /api/analyze?surah=1&ayah=1` — يستقبل ملف صوتي (`audio`, multipart)
  ويرجّع نتيجة التحليل: النتيجة (score)، عدد الكلمات الصحيحة/تحتاج
  تحسين/الخطأ، وتفاصيل كل حكم مخالَف. الشكل مطابق تمامًا لما هو معروض
  بتصميم شاشة التلاوة.

مثال:
```bash
curl -F "audio=@sample.wav" "http://localhost:8000/api/analyze?surah=1&ayah=1"
```

## إيش حقيقي وإيش Mock حاليًا

- **حقيقي:** شكل الـ API نفسه (العقد/contract) — الحقول، الأسماء، شكل
  الاستجابة. هذا ما يتغير حتى لما يدخل الموديل الحقيقي.
- **Mock حاليًا:** التحليل نفسه (`model_adapter.py` → `MockModelAdapter`)
  يرجّع نفس نتيجة البسملة الموجودة بالتصميم دائمًا، بغض النظر عن الصوت
  المُرسَل. هذا مقصود — يخليك تبني وتختبر باقي المنتج (الواجهة، تسجيل
  الصوت، حفظ التقدّم...) بدون انتظار الموديل.

## طريقة الترقية للموديل الحقيقي

1. شغّل `../colab/tajweed_baseline_eval.ipynb` على Colab/Kaggle (GPU) للتأكد
   من أداء `quran-muaalem` الأساسي على عيّنة من `qdat_bench`.
2. ابنِ ونفّذ طبقة "تفسير الأحكام" (sifat → حكم تجويد مسمّى) بناءً على نتائج
   التحقق البشري (راجع `tajweed-coach-validation-plan.md` بالمشروع) — هذي
   الطبقة موجودة كـ TODO صريح في `MuaalemModelAdapter._sifat_to_words`
   بملف `model_adapter.py`، وما تشتغل لين تُبنى وتُختبر فعليًا.
3. لما تصير جاهزة ومتحقق منها: غيّر سطر واحد بس في `get_adapter()` من
   `MockModelAdapter()` إلى `MuaalemModelAdapter()`. باقي الكود ما يتغيّر.

## اللي ناقص لمنتج حقيقي (خارج نطاق هذا الهيكل)

- نص القرآن كامل (حاليًا بس آية وحدة تجريبية) — يحتاج مصدر بيانات حقيقي
  (Uthmani script) لكل السور.
- صوت القارئ للاستماع (ميزة 🔊 استمع للقارئ) — يحتاج مصدر ملفات صوتية.
- قاعدة بيانات فعلية لحفظ تقدّم المستخدم بين الجلسات (حاليًا ما فيه حفظ).
- مصادقة/حسابات مستخدمين.
